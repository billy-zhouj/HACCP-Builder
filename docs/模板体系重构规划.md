# 模板体系重构规划（HACCP-Builder × 资料库全量整合）

> 编制日期：本规划**不受现有 26 个模板约束**，按"中国中小食品企业
> 完整质量安全体系"从零设计模板架构，全量整合 `D:\dsh\资料` 五套
> 模板库（SC 十一项制度 12 文件 / 记录表单 63 张 / 不合格品控制 15 /
> GMP 体系 9 / SSOP 9）+ FAO/FDA/CXC 原始标准。
> 本规划**取代**《模板库更新计划.md》的增量思路（该文映射表保留备查）。

## 一、设计原则

1. **体系完整**：覆盖 法规制度（SC）→ 前提方案（GB 14881/SSOP/Codex GHP）→
   HACCP 核心（7 原则）→ 运行控制 → 事件管理 五层 + 行业扩展，一单企业
   需要的全部文档。
2. **表单单一来源**：63 张 JL 记录表单只存在于资料库；SOP 的"相关记录"
   节引用 JL 编号，流程执行日志（接收/温度/纠正等）沿用内嵌表格先例。
3. **数据驱动优先**：能由用户已录入数据（facility/products/vendors/
   haccpTeam/工艺流程/危害分析）生成的段落不写占位符；确无数据源的
   用 [占位符] 并在 UI 提示。
4. **避免重复**：每个主题只有一个模板；现有 26 个按"保留/合并/改名/
   增强/拆分"处置，不新建同主题副本。
5. **可渐进实施**：按阶段落地，每阶段独立可交付、可回归。

## 二、新体系架构（6 层，45 核心模板 + 4 行业包）

```
L0 体系基础（9）      组织职责 · 文件记录 · 培训 · 健康 · 自查 · 管理评审 · 风险监测 · 供应商
L1 前提方案 PRP（12） 水冰 · 清洁消毒 · 交叉污染 · 手部 · 化学品 · 废弃物 · 虫害 ·
                     厂房环境 · 设备计量 · 仓储 · 班前检查 · 行为着装
L2 HACCP 核心（8）    团队产品 · 工艺流程图 · 危害分析 · CCP判定 · 监控 · 纠偏 · 验证 · 记录
L3 运行控制（11）     进货查验 · 生产控制 · 出厂检验 · 实验室 · 留样 · 标签 · 过敏原 ·
                     添加剂 · 温度 · 仓储物流运输 · 销售台账追溯
L4 事件管理（5）      不合格品 · 投诉 · 召回 · 事故应急 · 食品防护
L5 行业扩展（4 包）   饮料包材 · 水产出口 · 中央厨房 · 酿造发酵
```

## 三、记录表单挂接方案

1. 每个 SOP 末尾"相关记录"节列出对应 JL 表单编号（如 incoming_inspection →
   JL-01-01/02/03/07），生成时同时输出**记录清单**。
2. 流程执行类 SOP（接收/温度/纠正/投料/留样）内嵌**最小日志表**
   （沿用现有 receiving 先例），完整表单仍以资料库为准。
3. 表单编号与资料库 README 交叉引用一致，改表单不动 SOP，改 SOP 不动表单。

## 七、待确认决策点

1. **模板数量**：45 核心 + 4 行业包是否一次规划到位，还是先做 L0+L1+L4（法规强制面）？
2. **合并策略**：现有 26 个中的合并组（供方 3→1、接收+原料检验 2→1 等）是否接受——合并后 UI 更简洁，但需迁移旧文档。
3. **数据模型**：新增 AdditiveData/LabEquipmentData 与 FacilityProfile 扩展字段，是否接受"只增不改 + 增量迁移"？
4. **行业包**：4 个行业扩展包优先级（建议水产出口 > 中央厨房 > 饮料 > 酿造）。
5. **向导重构**：sops 页按新层级分组展示，是否同步调整向导步骤顺序（如自查/管理评审进 gmp 步骤）？
6. **规划文档**是否同步 `D:\dsh\资料` 随资料库推送 GitHub？
